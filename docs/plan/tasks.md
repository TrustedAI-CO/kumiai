## Test Plan

### Affected Routes
- `DELETE /api/v1/projects/{id}` — cascade, agent teardown, disk untouched
- `POST /api/v1/projects/{id}/restore` — new surface
- `POST /api/v1/projects` — recreate at a previously-deleted path (R6)

### Key Interactions to Verify
- Delete a project with live sessions → sessions stop, board no longer lists them
- Delete → recreate at same path → succeeds
- Delete → restore → project and its children return; sessions are not running

### Edge Cases
- Child deleted *before* the project, then project restored → child stays deleted (R2/R5)
- Interrupt raises for one of several sessions → delete still completes (R4)
- Restore onto a path another live project has taken → refused with the conflict named (R4)
- Restore a project that was never deleted → rejected (R3)
- Delete a project with zero sessions and zero tasks → no error

### Critical Paths
- delete → recreate → restore-conflict is one continuous story; test it end to end
- Migration on a copy of the real `~/.kumiai/kumiai.db`, not just an empty schema
